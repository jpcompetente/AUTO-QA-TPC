# AUTO-QA TPC Frontend

This Vite app is the active frontend for the project.

## Run

- `npm run dev`
- `npm run dev:https`
- `npm run build`
- `npm run lint`

## Behavior

The app starts with the login screen, then routes into admin, operator, or super admin panels based on the JWT role returned by Django.

## HTTPS For LAN Camera Access

Camera access on a LAN IP requires a secure context. The Vite dev server will use HTTPS automatically when it finds a trusted local cert pair in `frontend-vite/certs/`:

- `frontend-vite/certs/localhost.pem` and `frontend-vite/certs/localhost-key.pem`
- or any matching `*-key.pem` / `*.pem` pair generated by `mkcert`

You can also point Vite at explicit files with these env vars:

- `VITE_HTTPS_CERT_FILE`
- `VITE_HTTPS_KEY_FILE`

Recommended trusted local cert flow:

1. Install `mkcert` on your machine.
2. Run `mkcert -install` once to trust the local CA.
3. Generate a cert for your LAN host and localhost, for example:

```bash
mkcert localhost 127.0.0.1 ::1 192.168.1.10
```

4. Save the generated cert and key in `frontend-vite/certs/`. The server will auto-detect matching `*.pem` and `*-key.pem` pairs, including files like `localhost+2.pem` and `localhost+2-key.pem`.
5. Open the app using `https://<your-lan-ip>:5173`, not `http://`.
6. If the browser still shows an invalid certificate warning, the cert is either not trusted by the OS/browser yet or it does not include the exact LAN IP you opened. Regenerate it with that IP in the `mkcert` command.
7. Start the dev server with:

```bash
npm run dev:https
```

Troubleshooting note:

- If you already have a cert pair in `frontend-vite/certs/` but the browser still warns, re-run `mkcert -install` and regenerate the cert with the current LAN IP.
- If you switch networks, the LAN IP often changes, so the cert must be regenerated for the new IP.

If you prefer a tunnel, run the frontend behind an HTTPS tunnel such as ngrok or Cloudflare Tunnel and point `VITE_API_BASE_URL` / `VITE_WS_BASE_URL` at that HTTPS origin.
